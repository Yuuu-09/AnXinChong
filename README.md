# 安心充

**让预付消费的信任建立在透明规则上，让会员关系成为可持续连接的链上资产。**

安心充是构建在 Monad 上的稳定币预付消费与会员优惠协议。消费者购买储值卡或次数卡，预付款进入商家的独立智能合约金库；每次消费由商家与消费者共同签名确认，再由合约完成扣款和分账。消费者也可以按照购买时约定的规则，单方发起退款退出。

我们希望从日常的充值、办卡和消费出发，建立一套开放的商业协议：让资金流转可验证，让会员权益有据可查，并让长期积累的客商关系与消费记录支持更多应用。

## 项目愿景

预付消费本质上是消费者用未来的消费承诺，换取商家的优惠。但在传统模式中，商家往往在提供服务之前就取得全部资金，消费者需要承担资金被挪用、商家停业或退款规则不透明的风险。与此同时，会员关系与消费记录通常留在各个商家或平台的封闭系统里，难以跨应用使用。

稳定币支付是当前Crypto市场最重要的赛道之一，但在广大C端市场始终没有找到突破口。会员预付的安全资金托管和结算正是稳定币与智能合约具有独特优势的场景，是传统法币支付体系无法低成本实现的。

安心充希望让消费者、商家与服务提供者围绕一套共同的规则协作：

- **消费者安心预付**：未结算的本金由合约托管，消费需要本人确认，退出规则在购买时确定。
- **商家以服务获得收入**：通过储值优惠和次数套餐建立长期客户关系，随双方确认的消费取得收入。
- **渠道与邀请者透明获益**：获客和接入服务的分佣条件提前约定，由合约随结算执行。
- **生态共享可验证的商业记录**：会员关系、消费与结算记录沉淀在链上，为新的服务和应用提供基础。

## 协议如何运作

### 1. 商家发布会员计划

商家注册店铺后，工厂合约为其创建独立金库。商家可以发布两类计划：

| 计划类型 | 消费方式 | 示例 |
| --- | --- | --- |
| 储值卡 | 按购买时固定的折扣率扣除本金 | 充值 500 USDC，享九折；原价 100 USDC 的消费扣除 90 USDC |
| 次数卡 | 按购买时固定的优惠单价结算，扣减对应次数 | 购买 10 次服务，每次优惠价 58 USDC；使用一次释放 58 USDC |

计划修改会生成新版本，已购买会员卡的经济条款保持不变。每笔购买独立记账，不同批次的本金、折扣和权益分别管理。

### 2. 消费者购买，资金进入金库

消费者连接钱包并注册链上用户资料，选择计划、确认优惠及退款规则后，以 USDC 购买。购买款直接进入该商家的金库，形成对应的会员账户，此时不会立即分给商家或渠道。

### 3. 双方确认消费，合约完成结算

商家创建并签署账单，通过二维码或链接交给消费者。消费者核对金额、扣除次数及剩余权益后签名，提交链上结算。

合约校验双方签名、账单期限、序号及账户余额，在同一笔交易中扣减权益，并按购买时确定的规则向商家、渠道和邀请者分账。已结算账单无法重复执行。

### 4. 消费者按约定规则退出

消费者无需商家审批即可发起退出。合约根据历史消费计算已享受优惠的补差，优先从剩余本金中结算，再将余款退回消费者；补差以剩余本金为上限，无需额外补款。

例如，充值 500 USDC 享九折，消费原价 200 USDC 的服务后，已扣除 180 USDC、剩余本金 320 USDC。此时退出需补回已享受的 20 USDC 优惠，最终退款为 300 USDC。若可退金额为零，消费者仍可主动确认退卡；未主动退出时保留剩余权益。

## 当前实现

安心充采用静态前端直连链上合约的架构，当前版本无需独立业务后端或业务数据库。

| 组成 | 实现与职责 |
| --- | --- |
| 用户注册合约 | 钱包绑定唯一 handle 与可修改昵称，供消费者和商家共用 |
| 工厂合约 | 注册商家、部署并登记独立金库，不接收购买款或调拨本金 |
| 商家金库 | 管理会员计划、购买账户、双签消费、退款退出和分佣 |
| 消费者与商家前端 | 使用 React、TypeScript 和 Vite，提供购卡、会员卡包、商家管理、账单扫码及记录查询 |
| 链上交互 | 使用 viem 与钱包连接链上合约，账单使用 EIP-712 结构化签名 |
| 记录查询 | 从合约读取当前状态，通过链上事件恢复购买、消费、退款和分佣历史 |

各商家的资金与账目在不同金库内管理。工厂和金库均不可升级，没有管理员任意提取本金或改写历史经济条款的入口。账单签名绑定网络、金库、会员账户、条款、金额、序号与期限，双方均可主动使当前账单序号失效。

合约负责执行资金和权益规则，线下服务的完成情况仍需双方确认；当前版本不提供已结算消费的争议撤销机制。

目前已实现购卡、双签消费、主动撤销、退款退卡与累计分佣，并完成本地合约测试和双浏览器交互验证。用户注册合约与工厂已部署至 Monad 测试网，前端已接入实际部署地址；源码验证与测试网完整业务验收仍待完成。演示使用测试 USDC。

## 未来展望：从预付协议到开放的消费网络

当大量商户和消费者使用安心充，链上积累的将不只是交易金额，还包括持续形成的客商关系：谁成为了哪家商户的会员、何时购买、消费频率如何、会员权益如何使用，以及渠道和邀请者带来了哪些客户。这些可验证的关系与记录，将为协议带来更大的利用和扩展空间。

### 基于真实会员关系的精准获客

**商家可以向竞品商户的会员空投消费券。** 例如，一家新开业的咖啡店，可以依据协议中的链上会员记录，向另一家咖啡店的会员钱包发放首次到店优惠券，吸引已有同类消费需求的人群尝试自己的服务。

未来还可以结合近期消费频次、历史消费金额或会员状态设置领券条件，让营销从广泛投放走向基于可验证消费行为的触达。商家无需依赖另一家商户导出客户名单，消费者也可以使用钱包证明自己满足领取条件。

### 跨商家的会员权益与联合营销

不同商家可以基于共同的协议设计合作权益，例如健身房会员领取健康餐优惠、咖啡店与书店互发消费券，或多个商家联合推出消费任务与奖励。会员关系由此可以连接到更多消费场景。

### 面向商家和生态的开放应用

在链上记录之上，可以进一步构建商家经营分析、会员活跃度工具、渠道效果评估，以及聚合不同商家会员权益的钱包和应用。第三方服务可以读取同一套可验证记录，为商家提供运营工具，为消费者提供更方便的权益发现与管理入口。

## 本地运行

使用 Node.js 24.19.0 或更高版本、pnpm 11.25.0。在项目根目录运行：

```sh
pnpm install --frozen-lockfile
pnpm dev
```

打开 http://127.0.0.1:5173/。默认连接 Monad 测试网（Chain ID 10143），合约及资产地址保存在 `deployments/monad-testnet.json`。钱包需要测试 MON 支付 Gas，购卡还需要该配置指定的测试 USDC。先注册用户资料，再使用业务功能。

生产构建：

```sh
pnpm build
pnpm preview
```

构建产物位于 `web/dist/`；前端使用 Hash 路由，可部署到静态托管服务。

### 部署到 Vercel

导入本仓库，推荐 Root Directory 保持仓库根目录，Framework Preset 选择 Vite。仓库中的 `vercel.json` 已指定安装命令 `pnpm install --frozen-lockfile`、构建命令 `pnpm build` 和输出目录 `web/dist`。

若现有 Vercel 项目的 Root Directory 已选为 `web`，保留该设置即可，`web/vercel.json` 将输出目录设为 `dist`。Vite 会在构建前自动复制测试网部署配置，直接从 `web` 构建也不需要手动准备文件。默认无需设置环境变量；生产部署不要将 `VITE_DEPLOYMENT` 设为仅供本地开发的 `local.json`。

部署后 `/deployments/monad-testnet.json` 应返回 JSON，而不是 404。这个文件包含公开的测试网合约地址，必须与前端一起发布；`docs/` 和本地验收证据仍不上传。

## 开发检查

```sh
pnpm typecheck
pnpm format:check
pnpm test
pnpm abi:check
```

合约编译使用 Solidity 0.8.37、Osaka、optimizer 200 和 viaIR。执行 `pnpm compile` 可重新生成 ABI 和部署字节码；运行合约测试还需安装支持 Monad 的 Foundry 1.8.5：

```sh
pnpm test:contracts
```

浏览器集成测试使用隔离本地链和 MockUSDC，需先启动链 ID 为 31337 的 Anvil，再准备本地配置：

```sh
anvil --network monad --chain-id 31337
```

保持 Anvil 运行，在另一个终端进入项目根目录：

```sh
pnpm compile
pnpm local:deploy
VITE_DEPLOYMENT=local.json pnpm dev
```

在另一个终端运行 `pnpm test:e2e`；首次使用需安装 Playwright Chromium（`pnpm exec playwright install chromium`），或通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` 指定已安装的 Chromium 浏览器。切回测试网时停止本地前端，再执行 `pnpm dev`。本地部署清单、环境变量文件、依赖及构建产物均不提交至仓库。
